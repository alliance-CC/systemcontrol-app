# 現場サポートモード（/support）

プログラムがわからない現場のスタッフが、**社内ツールについての疑問をそのままの言葉で質問できる**モードです。
社内資料（このリポジトリの `knowledge/` フォルダ、および登録した GitHub リポジトリ）を根拠に回答し、
資料で解決しない場合は**開発者への依頼文**をその場で作成します。

---

## 1. 何ができるか

| できること | 説明 |
|---|---|
| 質問する | 「請求書ツールにログインできない」のような日常の言葉で質問できる |
| 根拠つきの回答 | 回答の下に「参照した資料」が出るので、現場が原典を確認できる |
| 稼働状況の反映 | 登録ツールの死活監視ステータス（🟢🔴🟡⚪）も踏まえて回答する |
| 開発者への依頼文作成 | 困りごとを、開発者が読んですぐ着手できる依頼文（件名＋本文）に整形する |
| GitHub Issue 起票 | `DEV_REQUEST_REPO` を設定していれば、依頼文を Issue 作成画面に流し込むリンクが出る |
| 参照資料の一覧表示 | 「いま AI が読めている資料」を画面右に常時表示。再読み込みボタンつき |

### 現場から見た流れ

1. 上部メニューの「現場サポート」を開く。
2. 困っていることを入力して「質問する」。
3. 回答と、根拠になった資料のリンクが表示される。
4. 解決しなければ「開発者への依頼文を作る」→ 内容を確認 →「依頼文をコピー」して開発チームへ送る。

## 2. 資料（ナレッジ）の置き方

AI が読むのは **Markdown / テキスト**（`.md` `.markdown` `.mdx` `.txt`）だけです。方法は 2 つあります。

### A. このリポジトリの `knowledge/` にフォルダを置く

```
knowledge/
├── sources.json          … 参照先の一覧
├── ツール管理システム/     … ツール 1 つ＝フォルダ 1 つ
│   ├── はじめてのログイン.md
│   └── パスワードの確認方法.md
└── 請求書ツール/           … フォルダを足すだけで参照先が増える
    └── 使い方.md
```

`knowledge/` 直下のフォルダは `sources.json` に書かなくても自動検出されます。
説明や担当者を画面に出したい場合だけ `sources.json` に登録してください。

### B. 別の GitHub リポジトリを読ませる

各ツールのリポジトリに README やマニュアルがある場合は、`knowledge/sources.json` に追記します。

```json
{
  "sources": [
    {
      "id": "juchu-kanri",
      "label": "受注管理ツール",
      "type": "github",
      "repo": "alliance-CC/juchu-kanri",
      "ref": "main",
      "include": ["README.md", "docs/**/*.md"],
      "description": "受注管理ツールのマニュアル",
      "owner": "開発チーム"
    }
  ]
}
```

| キー | 必須 | 内容 |
|---|---|---|
| `id` | ○ | 一意の識別子 |
| `label` | ○ | 画面に出る名前 |
| `type` | ○ | `github` |
| `repo` | ○ | `owner/repo` |
| `ref` | | ブランチ・タグ（既定：既定ブランチ） |
| `include` | | 取り込むパス。`docs/**/*.md` のような簡易パターン可。省略時はリポジトリ内の Markdown 全部 |
| `description` / `owner` / `tags` | | 画面表示用 |

- 取得はサーバー側のメモリに **30 分キャッシュ**されます。すぐ反映したいときは画面右下の「資料を再読み込み」を押してください。
- private リポジトリを読むには環境変数 `GITHUB_TOKEN`（**Contents: Read-only** の細粒度 PAT を推奨）が必要です。
- 1 ソースあたり最大 60 ファイル・1 ファイル 200KB までを取り込みます。

### 資料の書き方のコツ

- **1 ファイル 1 テーマ**にし、`## ログインできないとき` のように**質問に近い見出し**を付ける。
  検索は見出しに強く反応するので、正答率が上がります。
- 手順は番号付きで、画面に表示されるボタン名をそのまま書く。
- エラー画面の文言をそのまま書いておくと、現場が同じ言葉で質問したときに当たります。

### 資料に書いてはいけないもの

**パスワード・API キー・トークンの実値は絶対に書かないでください。**
機密値はツール管理システム本体（AES-256-GCM で暗号化して保管）で管理します。
資料には「ツール管理システムの詳細ページで確認」とだけ書きます。

## 3. 仕組み

```
質問
 ↓
[1] 資料検索  … knowledge/ + GitHub の Markdown を見出し単位に分割し、
 ↓              日本語は 2 文字組・英数字は単語で照合してスコア上位を抽出
[2] 文脈作成  … 抽出した資料 + 登録ツールの稼働ステータス（機密値は一切含めない）
 ↓
[3] 回答生成  … Claude API（ANTHROPIC_API_KEY）で、現場向けの言葉に噛み砕いて回答
 ↓
[4] 依頼文作成 … 解決しない場合、困りごとを開発者向けの依頼文へ整形
```

- 検索は形態素解析器を使いません（追加インフラ・辞書が不要なため）。
- **`ANTHROPIC_API_KEY` が未設定でも動作します。**その場合は AI 生成のかわりに、
  該当した資料の本文をそのまま提示するフォールバックになります。依頼文もテンプレートで作成されます。
- API 障害時も同じフォールバックに落ちるため、現場の作業は止まりません。

## 3.5 質問ログ（管理者向け）

現場から届いた質問は `support_logs` タブに 1 行ずつ記録されます（日時・ログインID・質問文・資料に当たったか・依頼を勧めたか）。
**回答本文は保存しません。**

管理者は `/support/logs` で次を確認できます。

- **資料に当たらなかった質問**（多い順）＝ 次に書くべき資料の候補
- 資料で答えられた質問（＝資料が効いているもの）
- 最近の質問一覧

未解決の質問が見つかったら、その**質問の言葉をそのまま見出しにして** `knowledge/<ツール名>/FAQ.md` に足してください。
テンプレートは `docs/FAQ_テンプレート.md` にあります。

質問文には現場が機密を書いてしまう可能性があるため、この画面は **admin のみ**が開けます。
`support_logs` タブを作らなければ記録は行われません（現場サポート自体は通常どおり動きます）。

## 4. セキュリティ上の扱い

本モードは既存のセキュリティ方針（`CLAUDE.md`）をそのまま引き継ぎます。

- **ログイン必須**：`/support` と `/api/support/*` はセッション検証の対象です（`/api/support/sync` はトークンでも可）。
- **機密値を AI に渡さない**：回答の材料に含めるのは資料本文と、ツール名・稼働ステータスだけです。
  `details_json` の機密値（暗号化済み）は復号も送信もしません。
- **パスワードを答えさせない**：システムプロンプトで、値そのものを回答に書かず
  「ツール管理システムの詳細ページで確認」と案内するよう指示しています。
- **依頼文の伏字**：現場が依頼文にパスワードを書いてしまった場合、AI 生成時は伏字に置き換えます
  （テンプレート生成時は置換しないため、送信前に内容を確認してください）。
- **参照範囲の限定**：ローカル資料は `knowledge/` 配下のみ。`../` を含むパスは拒否します。
- **外部送信**：`ANTHROPIC_API_KEY` を設定すると、質問文と抽出した資料が Anthropic API に送信されます。
  資料に機密値を書かない運用が前提です。

## 5. 導入手順（管理者向け）

1. `.env` に `ANTHROPIC_API_KEY` を設定する（未設定でも資料検索として動作します）。
2. 必要に応じて `GITHUB_TOKEN`（private リポジトリを読む場合）、`DEV_REQUEST_REPO`、`DEV_REQUEST_CONTACT` を設定する。
3. `knowledge/` にツールごとのフォルダを作り、現場向けのマニュアルを Markdown で置く。
4. 他リポジトリの資料を使う場合は `knowledge/sources.json` に追記する。
5. `node scripts/check-knowledge.mjs 'ログインできない'` で、資料が読めているか・現場の言葉で当たるかを確認する。
6. デプロイ後、`/support` を開いて画面右に資料が並んでいることを確認する。

### 運用のコツ

- 現場から同じ質問が 2 回来たら、その回答を資料に追記する。これを繰り返すほど回答精度が上がります。
- 依頼文が作成されたら、対応後に「どう直したか」を資料へ 3 行でも書き足しておくと、次回は AI が答えられます。
