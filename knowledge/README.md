# knowledge — 現場サポートモードが読む資料置き場

現場サポートモード（`/support`）の AI は、このフォルダと `sources.json` に登録した GitHub リポジトリの
Markdown を読んで、現場からの質問に答えます。

## ツールを 1 つ増やしたいとき

### A. このリポジトリにフォルダを置く場合

1. `knowledge/` の下にツール名のフォルダを作る（例：`knowledge/請求書ツール/`）。
2. その中に Markdown（`.md`）でマニュアルや FAQ を置く。ファイル名は日本語で構いません。
3. コミットしてデプロイすると、次のアクセスから AI が読めるようになります。

`sources.json` に書かなくても `knowledge/` 直下のフォルダは自動で検出されますが、
担当者や説明を出したい場合は `sources.json` に登録してください。

### B. 別の GitHub リポジトリを読ませる場合

`sources.json` の `sources` に追記します。

```json
{
  "id": "juchu-kanri",
  "label": "受注管理ツール",
  "type": "github",
  "repo": "alliance-CC/juchu-kanri",
  "ref": "main",
  "include": ["README.md", "docs/**/*.md"],
  "owner": "開発チーム"
}
```

- `include` を省略すると、リポジトリ内の Markdown をすべて対象にします（最大 60 ファイル）。
- private リポジトリを読む場合は、環境変数 `GITHUB_TOKEN`（Contents: Read-only）が必要です。
- 追加後は画面右の「資料を再読み込み」を押すと、その場で反映されます。

## 書き方のコツ（現場が答えを得やすくなります）

- 1 ファイル 1 テーマ。`## ログインできないとき` のように、**質問の形に近い見出し**を付ける。
- 手順は番号付きで、押すボタン名をそのまま書く。
- 「エラー画面に出る文言」をそのまま書いておくと、現場が同じ言葉で検索したときに当たります。

## 置いてはいけないもの

**パスワード・API キー・アクセストークンなどの実際の値は絶対に書かないでください。**
機密値はツール管理システム本体（暗号化して保管）で管理し、資料には
「ツール管理システムの詳細ページで確認」とだけ書きます。
